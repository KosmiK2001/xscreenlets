# Схема конфигов xscreenlets (основная, для демона и всех плагинов)

## Каталоги (~/.config/xscreenlets/)

- `.plugins/` — РЕАЛЬНЫЕ конфиги всех инстансов. Плагины читают и пишут
  только сюда (через xs_core_plugin_conf / conf_flush).
- `plugins/` — не используется. Миграция из неё происходит автоматически
  при старте демона, после чего каталог удаляется.
- `plugins_on/` — ТОЛЬКО для демона: symlink'и на конфиги в `.plugins/`.
  Демон запускает инстанс на каждый `*.conf` symlink здесь.
  Плагины и всё остальное сюда ничего не пишут и symlink'и не создают
  (кроме кода демона).

## Имена инстансов

Формат: `тип-UUID8-user_label` (пример: `launcher-9f4c2a1d-blank_label`).

- тип — имя плагина (clock, calendar, launcher, ...).
- UUID8 — короткий случайный hex (8 символов), генерится при создании
  инстанса; допускает много копий одного типа.
- user_label — пользовательская метка, по умолчанию `blank_label`.
  Хранится в конфиге (ключ `user_label` в секции инстанса) и в имени
  файла. Смена метки в Properties меняет ТОЛЬКО ключ user_label в
  конфиге, файл НЕ переименовывается (UUID — стабильный якорь).

## Обязательные правила для всех плагинов (текущих и будущих)

1. Секция конфига = имя инстанса (= имя файла без .conf).
2. Ключ `user_label` обязателен; отсутствие = `blank_label`.
3. Плагин не знает о plugins_on: только демон им управляет.
4. Новые инстансы: демон генерит имя (UUID8), пишет конфиг в `.plugins/`
   и создаёт symlink в `plugins_on/`.
5. Удаление инстанса: демон убирает symlink; конфиг в `.plugins/`
   сохраняется (можно включить снова).
6. Мёртвый symlink (конфиг удалён вручную): демон при старте показывает
   диалог — Удалить symlink / Указать другой конфиг (file chooser
   смотрит в `.plugins/`) / Отмена.

## Для ассистентов

- Не создавать конфиги руками в plugins_on и не писать в `.plugins/`
  вне API демона (xs_core_plugin_conf*).
- При добавлении нового плагина: ничего дополнительно не нужно — имя
  нового инстанса генерит демон.
