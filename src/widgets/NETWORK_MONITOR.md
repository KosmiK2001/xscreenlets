# network_monitor

Сетевой applet: скорости up/down по выбранному интерфейсу с историей в
графике. Написан по образцу `disk_monitor` — тот же каркас окна, то же
скругление через X shape, та же подгонка координат и текста. Исходники
`disk_monitor` при этом не используются и не меняются: у плагина своё
core.

## Что показывает

- имя интерфейса и его IPv4-адрес (если адреса нет — только имя);
- текущие скорости download и upload;
- накопленный трафик с момента загрузки по каждому направлению;
- график истории в двух режимах: `split` (два поля рядом) и `combined`
  (одно поле, обе серии в нём).

## Источники данных

Скорости берутся из `/proc/net/dev`: первый столбец Receive — bytes
received, девятый Transmit — bytes transmitted. Точно как в conky.

**Оборот счётчика.** Счётчики 32-битные и переполняются — на `wan0`
набегает 28 ГБ, то есть это не теория. Когда текущее значение меньше
предыдущего, `nm_rate_bytes_per_second()` возвращает -1, applet кладёт в
историю ноль и сбрасывает baseline. Без этого в графике вылезал бы
ложный скачок на ~4 Гигабайта.

**Первый тик** только создаёт baseline и в историю не попадает: иначе
первый график начинался бы с полной высоты.

**Тип интерфейса** определяется по sysfs, а не по имени:

| Тип | Признак |
|---|---|
| физический | `type=1`, есть MAC |
| мост | каталог `/sys/class/net/<if>/bridge` |
| туннель | `type=65534` (ARPHRD_NONE): tun, tap, wireguard, vpn |
| программный | `type=1` без MAC: ifb, veth |
| loopback | `lo` |

## Зазор между подписью и числом

`series<N>_label_x` и `series<N>_x` — две независимые координаты, и число
всегда остаётся на своей: если элементы пересеклись, уезжает подпись.

Подпись при шрифте `Sans 8` шириной около 22 px. Оставляйте между концом
подписи и началом числа хотя бы `NM_VALUE_GAP` (6 px), иначе подпись
уедет вправо за число:

    series0_label_x=6   -> подпись 6..28
    series0_x=34        -> число с 34, зазор 6, подпись на месте

    series1_label_x=156 -> подпись 156..178
    series1_x=177       -> число с 177, пересечение на 1 px
                         -> подпись уедет на 228, строка прочитается
                            как «64.4 KiB/s Up:»

Это не ограничение, а требование: свести координаты так, что между
элементами не остаётся места, нельзя.

## Цвета

Цвет серии берётся из `series<N>_color` — именно этот ключ пишет диалог
Properties. `rx_color` и `tx_color` читаются только если
`series<N>_color` в конфиге отсутствует: это legacy-ключи, оставшиеся
от первого варианта плагина, где серии назывались по направлению.

Принимаются два формата, одновременно:

    rgba(51,191,255,255)   и   rgb(51,191,255)      значения 0..255
    0.200000,0.749020,1.000000,1.000000              значения 0..1

Первый — тот, что пишет GtkColorButton и что лежит в примере конфига.
Второй пишет сам диалог при сохранении. Пробелы с обеих сторон от
запятой и перед скобкой допустимы, регистр не важен, `rgb()` без
альфы даёт непрозрачный цвет. Нераспознанное значение молча
заменяется значением по умолчанию.

Цвет **текста** серии (подпись, число скорости, сводка) задаётся
отдельно — ключом `series<N>_text_color`. Если его нет в конфиге, берётся
цвет заливки: так выглядели все конфиги до разделения. Разделение
полезно, чтобы держать подписи белыми, не теряя цвет заливки графика.

Мельше ещё разделение на подпись и число:

- `series<N>_label_color` — подпись `Down:` / `Up:`;
- `series<N>_value_color` — число скорости.

Оба по умолчанию берут `series<N>_text_color`, то есть при отсутствии
ключей подпись и число остаются того же цвета, что и раньше.

Шапка тоже разделена надвое: `wan0` слева, адрес прижат к правому краю,
у каждого свой цвет.

- `header_ifname_color` — имя интерфейса;
- `header_ip_color` — адрес.

Оба по умолчанию берут общий `text_color`. Если адреса нет (ifb, tun без
адреса), рисуется только имя — без висячего двоеточия.

## Разделение в режиме Split

Две половины разделены зазором в 8 px и вертикальной линией в цвет
рамки. Без зазора заливки смыкались бы в одну фигуру, и не было бы видно,
где кончается download и начинается upload — а это ровно то, ради чего
режим раздельный.

В узком окне зазор сжимается (`MIN(8, (width-4)/4)`), но остаётся
положительным, а половины не схлопываются в ноль. При ширине 420:
первая половина 2…212, зазор, вторая 220…418.

## Шкала

Шкала **общая** для обеих серий в любом режиме. Это смысл графика: 11
Мбайт должны выглядеть выше, чем 100 килобайт. Раздельные максимумы
превращали бы upload в размазанную полосу у нижнего края, и сравнивать
направления на глаз было бы нельзя.

Порядок выбора предела:

1. `graph_max_kib` из настроек, если больше нуля — ручная константа
   держит высоту постоянной при ровном трафике (как 95 для 100 Мбит в
   конфигах conky);
2. иначе — максимум наблюдённой истории.

## Подписи

Подпись каждой серии редактируется, положение переключается между
«внутри графика» (метка и значение одной строкой) и «снаружи» (подпись
над значением). В режиме «снаружи» занимается отдельная строка, поэтому
координаты разведены по вертикали: header `y=2`, подпись `y=12`,
значение `y=21`. При совпадении строк подпись накладывалась на строку
интерфейса, и обе исчезали.

## Цвета

RGB-only: `series0_color`, `series1_color`, `text_color`. Настоящая
прозрачность остаётся только у `graph_background_color` и
`border_color` — у RGB-only кнопок GTK возвращает alpha 1.0, и
сохранение обнуляло бы её.

## Координаты

Config хранит координаты в design-пикселях (420×220), renderer
пересчитывает их в live-координаты и не меняет сохранённые значения.
Подгонка текста учитывает ореол восьминаправленной тени (±3 px), а
прозрачный текст клипается по округлённому контуру окна.

## Сборка и тесты

```sh
make build/network_monitor.so
make test          # 78 проверок network_monitor
```

Тесты покрывают: парсер `/proc/net/dev` (включая битый ввод и точное
совпадение имени), оборот счётчика, насыщение при переполнении,
классификацию интерфейсов на фикстуре sysfs, сохранение alpha, подгонку
координат, кольцо истории и сглаживание.
